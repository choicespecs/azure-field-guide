Chapter 6

Tooling & infrastructure as code

The portal is for exploring. Real environments are built with code and pipelines: the CLI, an IaC language and a CI/CD system.

ToolWhat it isWhen you use it
Azure portalWeb UI at portal.azure.comExploring, troubleshooting, one-off checks. Every blade's "Export template" and JSON view teach you the underlying resource shape.
Azure CLI (az)Cross-platform command lineScripting, quick queries, CI pipelines. --query uses JMESPath to filter output.
Azure PowerShell (Az)PowerShell moduleWindows-heavy shops, object-pipeline scripting
Cloud ShellBrowser shell with CLI, PowerShell, Terraform, kubectl preinstalledWhen you cannot install tools locally
BicepMicrosoft's declarative IaC language; compiles to ARM JSONAzure-only shops. Day-zero support for new resource types, no state file to manage.
ARM templatesThe JSON format ARM natively understandsYou will read them more than write them; Bicep replaced hand-written ARM.
Terraform (azurerm, azapi)HashiCorp's multi-cloud IaCMulti-cloud teams, existing Terraform expertise. Keep state in a locked storage account backend.
Azure Verified Modules (AVM)Microsoft-maintained Bicep and Terraform modulesStarting points that follow Well-Architected defaults
Azure Developer CLI (azd)App-centric workflow: azd up provisions infra + deploys code from templatesSpinning up full sample apps quickly; developer inner loop
Azure DevOpsBoards, Repos, Pipelines (YAML), Artifacts, Test PlansMany enterprises run CI/CD here. Key pieces: YAML pipelines, service connections, environments and approvals.
GitHub ActionsCI/CD in GitHub with azure/login via OIDC federationModern default for new projects; no stored client secrets
Azure Resource GraphKQL query engine across all your subscriptions' resourcesInventory questions: "every public IP in the company"
VS Code + Azure extensionsBicep language server, Functions, Resources explorersDaily editing; the Bicep extension's IntelliSense is the fastest way to discover resource properties
Azure CLI essentials
# sign in and pick a subscription
az login
az account list -o table
az account set --subscription "My Sub"

# resource groups and inventory
az group create -n rg-demo-dev -l eastus2
az resource list -g rg-demo-dev -o table
az resource list --query "[?type=='Microsoft.Web/sites'].name" -o tsv

# deploy Bicep (what-if previews the diff)
az deployment group what-if -g rg-demo-dev -f main.bicep
az deployment group create -g rg-demo-dev -f main.bicep -p env=dev

# RBAC
az role assignment create --assignee <objectId> \
  --role "Storage Blob Data Reader" --scope <storageAccountId>
az role assignment list --assignee <objectId> --all -o table

# everyday service commands
az webapp log tail -n app-demo -g rg-demo-dev
az aks get-credentials -n aks-demo -g rg-demo-dev
az keyvault secret show --vault-name kv-demo -n DbPassword
az group delete -n rg-demo-dev --yes --no-wait
Bicep: storage + managed identity access
param location string = resourceGroup().location
param env string
param appPrincipalId string

resource st 'Microsoft.Storage/storageAccounts@2023-05-01' = {
  name: 'stdemo${env}${uniqueString(resourceGroup().id)}'
  location: location
  sku: { name: env == 'prod' ? 'Standard_ZRS' : 'Standard_LRS' }
  kind: 'StorageV2'
  properties: {
    allowBlobPublicAccess: false
    minimumTlsVersion: 'TLS1_2'
    allowSharedKeyAccess: false   // force Entra auth
  }
}

// Storage Blob Data Reader (built-in role ID)
var blobReader = '2a2b9908-6ea1-4ae2-8e65-a410df84e7d1'

resource ra 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  scope: st
  name: guid(st.id, appPrincipalId, blobReader)
  properties: {
    principalId: appPrincipalId
    principalType: 'ServicePrincipal'
    roleDefinitionId: subscriptionResourceId(
      'Microsoft.Authorization/roleDefinitions', blobReader)
  }
}

output blobEndpoint string = st.properties.primaryEndpoints.blob
Naming convention: most teams use the Cloud Adoption Framework pattern <type>-<workload>-<env>-<region>-<nnn>, e.g. rg-payments-prod-eus2-001, kv-payments-prod-eus2. Some resources (storage accounts, ACR) allow only lowercase letters and digits and must be globally unique. Ask your team what convention they use before creating anything.
