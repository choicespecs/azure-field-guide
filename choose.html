Which one do I pick?

Azure often has three or four services that look alike. These tables cover the comparisons that come up most in design reviews.

ServicePick it whenYou manageScale to zeroWatch out for
Virtual MachinesLift-and-shift, custom OS, licensed software, full controlOS, patching, runtimeNo (deallocate to stop compute billing)You own patching and backups; disks bill even when stopped
App ServiceWeb apps and APIs in .NET, Java, Node, Python, PHP, or a containerCode + configNoYou pay for the plan, not per app; many apps can share one plan
FunctionsEvent-driven bits: a queue message, timer, HTTP hook, blob uploadFunction codeYes (Flex Consumption / Consumption)Cold starts; execution time limits on consumption plans
Container AppsContainerized microservices and jobs without running Kubernetes yourselfContainer images + scale rulesYesNo direct Kubernetes API access; check feature gaps vs AKS
AKSYou need the full Kubernetes API, operators, service mesh, many teams on one platformWorkloads, node pools, upgrades, add-onsNode pools can scale to 0 (user pools)Real platform-team effort: upgrades, networking, security
Container InstancesRun one container quickly, a batch task, or a CI agentContainerBilled per second while runningNo built-in autoscale or load balancing
BatchLarge parallel HPC or rendering jobs across many VMsJob definitions, poolsPools can scale to 0Job scheduling model takes some learning
Static Web AppsSPA or static site with optional managed Functions APIFront-end buildN/A (free tier exists)The managed API is limited; link your own backend for more
ServiceShapePick it whenKey featuresNot for
Service BusEnterprise message broker (queues, topics)Commands and business transactions that must not be lost: "process order 123"Sessions (FIFO per key), dead-lettering, duplicate detection, transactions, scheduled messagesMillions of telemetry events per second
Event GridPush-based event router (pub/sub)Reacting to something that happened: "blob created", "resource deleted"Filters, retries, CloudEvents schema, MQTT broker, system topics for Azure servicesOrdered processing, large payloads
Event HubsPartitioned append-only log (Kafka-compatible)High-volume streams: telemetry, clickstream, logsPartitions, consumer groups, Capture to storage, Kafka protocol endpoint, retention/replayPer-message acknowledgement workflows
Storage QueuesSimple queue inside a storage accountCheap, basic background work; very large backlogsHuge capacity, HTTP API, very low costOrdering, topics, dead-lettering (you build it)
Web PubSub / SignalRReal-time push to browsers/clientsLive dashboards, chat, notificationsWebSockets at scale, managed connectionsServer-to-server messaging
ServiceLayerReachPick it whenExtras
Load BalancerL4 (TCP/UDP)RegionalDistribute traffic to VMs or scale sets; internal or publicHA ports, outbound rules, zone-redundant frontends
Application GatewayL7 (HTTP/S)RegionalPath-based routing, TLS termination, WAF in front of apps in a VNetWAF v2, autoscale, AKS ingress via Application Gateway for Containers
Front DoorL7 (HTTP/S)Global edgeGlobal entry point, CDN caching, multi-region failoverWAF, Private Link to origins (Premium), rules engine
Traffic ManagerDNSGlobalDNS-level routing for any protocol (priority, weighted, geographic, performance)Works for non-HTTP; failover is bounded by DNS TTL
ServiceModelPick it whenKey conceptsWatch out for
Azure SQL DatabaseRelational (SQL Server engine), PaaSNew relational apps, SaaS per-tenant DBsvCore vs DTU, serverless, Hyperscale, elastic pools, geo-replication, failover groupsNo SQL Agent or cross-database queries in the usual way
SQL Managed InstanceNear-complete SQL Server instance, PaaSMigrating existing SQL Server estates with Agent jobs, CLR, cross-DB queriesVNet-injected, instance pools, link to on-prem SQLHigher entry cost; deploys into a dedicated subnet
PostgreSQL / MySQL Flexible ServerOpen-source relational, PaaSOpen-source stacks, Django/Rails/Laravel appsBurstable/GP/Memory tiers, zone-redundant HA, read replicas, extensionsMajor-version upgrades need planning
Cosmos DBMulti-model NoSQL, globally distributedLow-latency at global scale, flexible schema, multi-region writesRequest Units (RU/s), partition keys, 5 consistency levels, change feed, vector searchA bad partition key is very expensive to fix later
Azure Managed RedisIn-memory key-valueCaching, sessions, rate-limiting, leaderboardsEviction policies, clustering, persistence, active geo-replicationAzure Cache for Redis is retiring; new work should use Managed Redis
Data Explorer / Fabric EventhouseAppend-heavy analytics (KQL)Log and telemetry analytics at huge scaleKQL, ingestion mappings, materialized viewsNot a transactional store
OptionWhat it doesTraffic pathUse when
Private EndpointGives a PaaS resource a private IP in your subnet (Private Link)Fully private; works from peered VNets and on-premDefault choice for locking down PaaS. Pair with Private DNS zones like privatelink.blob.core.windows.net.
Service EndpointExtends the subnet's identity to a service so its firewall can allow that subnetOptimized route, but the service keeps its public IPSimple, free, same-region; does not cover on-prem traffic
VNet integrationLets App Service/Functions make outbound calls into a VNetOutbound onlyYour web app needs to reach a private database. Combine with a private endpoint for inbound.
VPN GatewayEncrypted IPsec tunnel over the internetSite-to-site or point-to-siteHybrid connectivity on a budget
ExpressRoutePrivate circuit through a connectivity providerDoes not traverse the public internetPredictable bandwidth and latency for serious hybrid workloads
VNet peeringConnects two VNets over the Microsoft backboneNon-transitive by defaultHub-and-spoke designs; use a hub firewall or Virtual WAN for transit
OptionCopiesSurvivesRead from secondary?Typical use
LRS3 in one datacenterDisk / rack failure—Dev/test, data you can recreate
ZRS3 across availability zonesOne datacenter failing—Production default in zone-enabled regions
GRS / RA-GRSLRS + 3 async copies in the paired regionRegional outage (after failover)RA- variant onlyBackups, DR copies
GZRS / RA-GZRSZRS + 3 async copies in the paired regionZone and regional failureRA- variant onlyCritical production data

Blob access tiers are a separate axis from redundancy: Hot → Cool (30-day minimum) → Cold (90-day) → Archive (180-day, offline, hours to rehydrate). Lifecycle management policies move data between tiers automatically.
